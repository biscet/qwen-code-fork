# HomeChat

## Goal

Add a product switcher to the HomeCode desktop shell and a separate HomeChat surface for internet research. HomeChat conversations must not use HomeCode sessions, workspace context, local tools, attachments, or filesystem APIs.

## Product boundary

HomeChat is a separate React tree. It is rendered outside `DaemonWorkspaceProvider`, so opening it does not request workspace capabilities or create a HomeCode agent session. Its chat client calls only the authenticated `/homechat/*` daemon routes. The Settings and Daemon Status footer actions explicitly mount the existing administrative Web Shell panels in the main area. That separate provider is mounted only while a panel is open and receives no HomeChat messages; closing it restores the current chat and draft.

The `/homechat/*` routes are process-global and Vane-scoped; they are not primary-workspace or selected-runtime routes. The daemon forwards them to the loopback Vane service at a fixed address, and telemetry does not attribute them to a workspace. The client cannot choose another upstream. Requests accept only a message, a HomeChat-prefixed chat ID, and text history. The daemon fixes sources to the public web, fixes files to an empty list, chooses the configured Vane models itself, and adds a system instruction that denies knowledge of the user's computer and local data.

Vane owns HomeChat persistence and SearXNG-backed research. HomeChat IDs have their own prefix, and list/read/delete routes reject or hide all other Vane conversations.

## Interface

The sidebar mode control mirrors the compact HomeCode visual language and exposes the two surfaces as Harness and Chat. HomeChat uses a dedicated pixel wordmark and speech/search mark derived from the existing HomeCode grid.

The HomeChat sidebar contains only new chat, internet-chat history, and the shared Settings and Daemon Status actions. Mode descriptions read “Для кодинга” and “Для поиска информации”; mode marks are scaled by 1.25 within their existing navigation slots. The main view contains the transcript, research status, linked sources, and a text-only composer. It intentionally has no workspace, model, permission, attachment, terminal, tools, or computer controls.

### Visual parity with Harness

Render the mode picker in its own sidebar row between the native titlebar and the new-task action. Both surfaces use the existing Web Shell theme tokens, sidebar navigation styles, welcome wordmark sizing, composer shell and send button, and user-message bubble styles. The empty Chat view centers the wordmark and composer together; populated chats retain a scrolling transcript and an in-flow composer below it. Keep the internet label in the composer. HomeChat messages remain outside workspace providers; only explicitly opened administrative panels mount their own provider.

## Failure behavior

If Vane, its model provider, or web search is unavailable, the proxy returns a scoped HomeChat error. Streaming failures terminate the current reply without falling back to a HomeCode runtime or exposing local capabilities.
