# Настройки моделей HomeCode

В настройках нужна самостоятельная, всегда доступная категория «Модели». Сейчас управление моделями появляется только при наличии отдельных настроек категории Model и умеет выбирать, добавлять через мастер авторизации и удалять. Текущий local-coder — Qwen3.8-27B на Windows, OpenAI-compatible API, 128K. Существующие параметры этой модели сохраняются при редактировании.

## Решение

Использовать существующую навигацию настроек, палитру и типографику HomeCode. В основной области — плоский список подключений с названием, моделью, адресом и отметкой текущей модели. Редактор открывается на месте: название, ID модели, URL, скрытый API-ключ, имя переменной окружения, контекст, максимальный ответ, температура и top-p. Дополнительные параметры не перезаписываются. Сохранение явное, пустой ключ сохраняет существующий. Изменение адреса не должно неявно переносить секрет на другой сервис.

Отдельные строки подключения бесплатных Qwen3.8-27B: ModelScope и OrcaRouter. Пресеты заполняют точные ID и URL; пользователь вводит свой ключ. Доступность и условия проверены по официальным страницам 2026-09-05. Никакой автоматической подмены на другую модель или платного fallback.

ModelScope публикует дневные лимиты и остатки аккаунта и модели в заголовках ответа. Кнопка проверки выполняет один минимальный запрос с нейтральным текстом и показывает полученные лимиты с временем проверки. До проверки остаток неизвестен. OrcaRouter публикует ограничения частоты вместо фиксированной дневной/недельной квоты; показывать доступные заголовки и явно обозначать отсутствие опубликованного остатка. Не считать локальные вызовы полным расходом аккаунта.

## Слои и границы

- Новые маршруты настроек моделей принадлежат выбранному workspace runtime, с legacy-primary alias. Проверяют trust, generation и client ownership по существующим паттернам. Не используют primary fallback для неизвестного workspace.
- Чтение возвращает только разрешенные поля и признак наличия ключа. Запись обновляет одно точное подключение в выбранной области настроек и сохраняет остальные модели/параметры. Секреты не возвращаются в HTTP, SSE или ошибки.
- SDK передает выбранный workspace и scope. UI перезагружает список после сохранения; runtime sync использует существующий механизм.
- Проверка лимитов использует серверный ключ и только известные адреса бесплатных сервисов. Проверка не отправляет диалог или файлы проекта.
- Сохранить существующие действия удаления и авторизации. Удаление использует новый scoped DELETE по точному подключению с подтверждением в строке; старый мастер авторизации доступен для primary workspace. Не менять несвязанные изменения пользователя.

## Thinking и effort

Существующий popover модели в ChatEditor уже содержит оба управления. Для alias-моделей с явно заданными параметрами chat template добавляется preview возможностей. Канонические reasoning-настройки синхронизируются с существующими enable_thinking/reasoning_effort перед реальным запросом; preserve_thinking сохраняется. Для точного Qwen3.8-27B используются поддерживаемые low/medium/xhigh, для произвольных alias — явно доступные настройки. API нашей модели подтвердил aliases local-coder/qwen3.8-27b и контекст 131072.

После изменения подключения активная сессия обновляет генератор перед следующим запросом; выполняющаяся генерация не прерывается. Переименование ID/адреса использует точное соответствие старого подключения и не выбирает произвольную другую модель.

ModelSettingsPanel получает SDK-клиент, привязанный к activeWorkspaceCwd: общий workspace hook исторически привязан к primary и не используется для новых операций. Если проект наследует модели пользователя, вкладка показывает их; первое сохранение в проект создает override в выбранной области.
