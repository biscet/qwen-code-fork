# 桌面日志下载

[English](desktop-log-download.md) | [简体中文](desktop-log-download.zh-CN.md)

## 问题与当前状态

诊断另一台 Mac 上失败的对话轮次需要已安装应用的日志。桌面恢复页面可以打开
`desktop-runtime.log`，但常规 Web Shell 没有下载操作。桌面应用目前在每次启动时
清空该日志，重启后会丢失故障证据。该文件捕获 daemon 的 stdout 和 stderr，包括
daemon 错误与转发的 ACP 诊断信息。

## 提议的更改

在 daemon 状态工具栏添加带下载图标的紧凑描边“下载日志”按钮，复用 Web Shell
按钮样式，并提供英文、中文和俄文文案。即使状态数据无法加载或渲染，仍保留该
操作。显示保存中、成功和失败状态；取消原生对话框时不显示提示。仅在桌面应用
中显示此操作。

原生 `download_logs` 命令打开操作系统的保存对话框并写入 UTF-8 文本文件。调用方
不能传入源路径或目标路径。只有处于 bootstrap 来源或当前活动 daemon 来源的
主窗口可以调用该命令。此操作属于进程全局桌面操作，不解析或更改工作区运行时，
也不添加 daemon HTTP 路由。

启动时清空当前日志之前，将其最后 8 MiB 保存为 `desktop-runtime.previous.log`。
当前日志为空时保留已有的上次日志。保留操作失败时不得清空当前日志。导出两个
文件各自最后 8 MiB，并包含分节标题、明确的截断提示、桌面版本、系统/架构和导出
时间。采用有界尾部读取，不读取整个文件。运行期间的正常日志捕获保持不变。

在导出的副本中遮盖可识别的 authorization 头、bearer token、凭据字段、常见
API 密钥前缀和 URL 凭据。ACP 诊断上游已进行凭据脱敏；此额外处理覆盖原始 stderr。
这不保证任意用户生成的日志内容完全不含秘密。本地原始日志保持不变，保留有助于
诊断的工作区路径。

## 文件与范围

修改桌面原生命令/日志辅助代码及测试、daemon 状态 UI 及测试、小型原生桥接函数、
翻译、桌面 README，以及打包冒烟测试中过时的日志保留说明。不依赖对话数据库，
不导出对话或配置，不自动上传，不改变模型或提供方行为。Rust 依赖图中已存在
`regex`，本次将其作为直接依赖用于导出副本的脱敏。

## 验证与验收

test-engineer 在 `.qwen/e2e-tests/homecode-2.1.12/` 中分别记录全局 CLI 基线和
桌面基线。CLI 没有与原生保存对话框对应的操作。聚焦 Rust 测试覆盖保留机制、
有界 UTF-8 尾部读取、缺失日志、脱敏和来源拒绝。聚焦 DOM 测试覆盖仅桌面显示、
不传文件参数的原生命令调用、等待/成功/取消/错误状态，以及状态不可用时的渲染。
构建、类型检查和打包应用检查验证集成。原生保存对话框验证必须与模拟浏览器或
DOM 检查分开报告。
