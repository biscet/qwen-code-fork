# 桌面工作区 MCP 默认配置

[English](2026-09-10-desktop-workspace-mcp.md) | [简体中文](2026-09-10-desktop-workspace-mcp.zh-CN.md)

## 问题与现状

HomeCode 将五个远程 MCP 声明以及开发技能和代理安装到用户配置目录。
远程 Serena 无法访问客户端 Mac 上的项目；远程浏览器的 localhost 指向服务器。
打开受信任工作区时不会创建项目默认配置。test-engineer 的工具白名单也不包含 MCP。

## 预期行为

加载受信任的桌面工作区运行时之前，初始化缺失的项目 MCP 设置、技能和代理。
覆盖主工作区、恢复的工作区、动态添加的工作区和信任变更后重建的工作区。
不受信任工作区及 HomeChat 不初始化这些能力。保留自定义声明、现有文件、禁用的工具
和用户主动删除的内容。用户本地的工作区安装记录保证初始化幂等。仅对安装器生成的准确 MCP 配置
自动批准；任意已有项目声明仍需通过原有配置审批。

将本地 Node REPL、Serena、Playwright、Chrome DevTools、所需解释器及一个 Chromium
打包到应用中。根据安装后的应用位置解析可执行文件，不使用构建机器路径。
每个 MCP 进程都在选定工作区启动。Serena 在需要时初始化该项目元数据，并保留现有配置。
各连接的浏览器会话和 REPL 状态独立。可写缓存放在应用之外。
空项目创建首个 TypeScript 和 Python 文件后，无需重启 Serena 即可发现符号。
安装的技能文件不参与项目语言判定。
Home AI Research 保持为经过身份验证的 HTTPS 服务，使用现有 LOCAL_QWEN_API_KEY
和随应用提供的公开局域网证书。

## 代理指令

Qwen 和 Codex Harness 应使用可用的工作区 MCP 进行语义代码操作、JavaScript 执行及
浏览器验证。Qwen 在有帮助时委派范围明确、相互独立的开发任务。
Codex 原生委派保持禁用，因为子代理工具和审批请求尚未建立工作区所有者路由。
以实际连接的工具清单为准；说明依赖缺失或连接失败，不虚构验证成功。
test-engineer 获得相关 MCP 能力，同时保留只观察和报告、不得修改产品源码的限制。
HomeChat 继续保持隔离。

## 范围及涉及组件

桌面默认配置、运行时打包及测试；守护进程工作区初始化；Qwen/Codex Harness 指令和
针对性测试；内置开发代理；桌面发布版本及文档。不修改模型路由，不部署远程服务，
不导出用户凭据，不执行 Git 提交或推送。

## 验证及验收

使用干净用户配置和两个不同的临时工作区验证自动创建、继承、重复启动、自定义配置保留、
不受信任状态拒绝及真实 MCP 工具调用。证明本地文件及符号访问、REPL 状态独立，
以及浏览器能访问客户端 localhost 网站。验证代理可见性及工具过滤。
运行针对性测试、构建、类型检查和打包，并审查任务差异两遍。
生成 Apple Silicon DMG，验证完整临时签名、镜像完整性及挂载后应用和运行时冒烟测试。
应用打包时保留 Chromium 框架的目录符号链接；挂载镜像中的每个运行时校验和条目
都必须可访问且与原值一致。
临时签名不是 Developer ID 签名或公证。第二台实体 Mac 的安装验证与移动应用后的
干净配置测试属于不同证据。

## 约束与待定问题

本次发布面向 Apple Silicon 和 macOS 15 或更新版本，与内置 Codex shell 的部署目标一致；
Chromium 本身要求 macOS 13。打包 TypeScript/JavaScript
和 Python 语言服务器；其他平台构建保留远程 MCP 默认配置。语义语言服务器可能需要对应语言工具链或首次下载；
使用 TypeScript 作为具体验收语言，并记录这一边界。没有未决产品选择。
