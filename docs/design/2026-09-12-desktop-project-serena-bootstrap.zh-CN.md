# 添加桌面项目时初始化 Serena 配置

[English](2026-09-12-desktop-project-serena-bootstrap.md) | [简体中文](2026-09-12-desktop-project-serena-bootstrap.zh-CN.md)

## 问题与证据

在隔离的 HomeCode 2.1.18 守护进程中，添加可信的空目录、TypeScript 项目和 Git
项目时会立即生成 `.qwen/settings.json`，但 `.serena/project.yml` 只有在运行时激活后
才出现。项目注册与 MCP 启动相互独立，因此已添加的项目可能看起来尚未配置完整。

用户提供的 HomeCode 2.1.17 日志确认客户端为 Apple Silicon，但不包含 MCP 发现结果
或模型请求体。另一次真实本地模型测试捕获的首次请求虽然包含桌面 MCP 指引，却
只有内置工具定义，没有延迟加载的 MCP 目录，尽管工作区显示服务已经连接。
ACP 直接通过聊天对象发送请求，绕过了常规客户端刷新后续 MCP 发现提示的路径。

## 行为

在可信桌面工作区引导期间、项目注册完成之前初始化内置 Serena 的项目配置。
通过内置启动器的初始化模式调用 Serena 自身的配置生成逻辑；不为生成配置而启动
持续运行的 MCP 服务或语言服务器。正常的 MCP 启动和按需工具发现机制保持不变。

仅对经过验证并获准的内置 Serena 定义执行该操作。保留自定义定义、禁用、排除或
拒绝的服务、不可信工作区以及已有项目配置的行为。保留安装器归属和环境校验，
防止项目配置替换可执行文件。初始化错误必须有时间限制且可见，但不能阻止使用
项目的其余部分。现有项目可在下次引导时初始化。

ACP 会话发送模型请求之前，应等待该会话的 MCP 发现完成，并支持取消，然后刷新
现有的 MCP 工具和服务器指引提示。复用常规客户端的提示机制，使后续增加和移除
工具的变化仍然可见，且不重复通知。会话创建继续保持非阻塞。保留延迟加载的工具
定义和 `tool_search`；无需修改系统提示的措辞。

## 验证与发布

使用隔离配置和空目录、仅含源码的目录、Git 目录、不可信目录，重复实际守护进程的
项目注册操作。断言配置在运行时激活之前存在，然后使用 Serena 查询项目内符号。
验证重复引导不会改变已有配置。通过真实本地模型完成 MCP 工具发现和成功的工具
调用。检查首次模型请求中的 MCP 目录，测试发现期间取消以及后续工具变更，
并将这些证据与连接清单分别报告。

执行针对性回归测试、构建、类型检查和两轮审查。为 Apple Silicon/macOS 15+
打包 HomeCode 2.1.19，验证运行时校验和、完整应用的临时签名、DMG 完整性和挂载后的
运行时启动。这些属于本机安装模拟；另一台 Mac 上的实际验收仍需单独确认。
