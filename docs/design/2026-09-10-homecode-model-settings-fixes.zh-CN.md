# HomeCode 模型设置修复

[English](2026-09-10-homecode-model-settings-fixes.md) | [简体中文](2026-09-10-homecode-model-settings-fixes.zh-CN.md)

## 问题与范围

HomeCode 2.1.12 在升级已初始化的配置时可能恢复已删除的预置模型。
修改设置后，已打开的 Harness 聊天仍显示旧模型名称；多个连接共用同一模型 ID
时，欢迎页面的输入框缺少推理控制。本次范围仅限这些错误及 HomeCode 2.1.13 安装包。

## 决策

- 仅在首次桌面默认设置安装凭据不存在时添加预置模型。
  后续默认设置迁移保留现有配置中的模型列表。
- 使用所选工作区的最新提供商目录更新模型显示信息。
  按提供商和端点的精确身份匹配连接。重命名改变不透明标识符时，
  更新目录及聊天选择状态中的标识符，不切换底层模型。
  保留仅运行时存在的模型和草稿中待应用的推理选项。
- 根据精确解析的连接生成推理预览，包括使用不透明标识符的连接。
  保留强制思考要求和各连接支持的推理级别。会话推理验证也使用同一连接，
  从而接受首次提示之前选择的选项。不得使用具有相同模型 ID 的其他端点来推断能力。
- 保持用户与工作区设置归属、凭据处理、无关默认设置及 ACP 选择标识符协议不变。
- 将所有 HomeCode 版本来源同步为 2.1.13；保留独立的上游 Qwen 运行时版本。

## 验证与验收

回归测试覆盖升级和重启后保留模型删除、重命名后活动聊天与欢迎页面的模型名称，
以及模型 ID 相同但端点设置不同的推理预览。隔离浏览器和模拟补全 API
验证设置界面、重启持久化及首次请求的推理参数。
打包前完成构建、类型检查、针对性单元测试和差异审查。

Apple Silicon DMG 必须通过磁盘映像验证、严格应用签名验证及打包运行时冒烟测试。
构建使用现有的临时签名流程；不声称具有 Developer ID 公证，
也不声称已在接收者的实体 Mac 上测试。
