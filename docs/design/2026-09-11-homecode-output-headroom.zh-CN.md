# 为 Windows Qwen 保留 HomeCode 输出空间

[English](2026-09-11-homecode-output-headroom.md) | [简体中文](2026-09-11-homecode-output-headroom.zh-CN.md)

状态：已为 HomeCode 2.1.17 实现；源代码、CLI 和网关验证已通过。

## 已确认的问题

后台 Explore 任务完成后，主代理恢复执行、读取文件，然后收到
`final_answer_not_formed / max_tokens`。Windows 任务 `7232` 于
2026-09-11 15:05:29 UTC 结束，恰好生成了 8192 个 token。保留的槽位参数为
`max_tokens=8192`、`n_predict=8192` 和 `reasoning_format=qwen`。
实际运行的原生进程配置了 8192 的推理预算和 16384 的默认总输出预算。
请求中较小的总预算覆盖了默认值。推理采样器用尽预算时，生成过程立即停止，
因此无法输出强制结束序列和最终回答。

Bifrost 请求 `7b6975dd-0896-4029-a2ee-167ba5b26653` 在 322932 ms 后记录了
同样的终止错误。适配器保留了请求限制。本次故障并非超时、队列溢出、GPU
故障或解析器拒绝导致。

HomeCode 打包的 Windows Qwen 配置仍将总输出上限设为 8192。客户端正确地将
配置的上限视为显式选择，所以不会替换为服务器默认值，也不会在重试时提高
该上限。SSE 的 HTTP 200 并不能证明生成成功完成。

## 变更与范围

将打包的 Windows Qwen 总输出预算设为 16384。对现有全局配置和受信任工作区
配置中已知家庭 Windows Qwen 路由的旧 8192 设置进行迁移，包括其 Bifrost
部署别名。支持现有的两种 OpenAI 提供者表示形式，并保留 JSONC 注释。
在安装回执导致跳过现有设置之前执行迁移。

每个设置位置只迁移一次，之后用户有意修改的值必须保留。保留缺失的设置或
模型、其他上限、自定义路由或协议、其他显式输出限制和显式较小的推理预算。
继续遵守已有的工作区信任与符号链接检查。不恢复已删除的默认项，也不扩大
独立的原生推理迁移范围。

保留推理启用状态、8192 原生推理预算、选定的 effort、采样、上下文大小、
模型、GPU 设置及工具执行规则。这是配置修复，不改变通用重试或响应解析。
新的总预算为强制阶段转换及最终输出留出空间，但不能保证任意模型响应都能
成功完成。

## 验证与验收

修改源代码前，使用全局 CLI 和隔离测试文件复现故障。使用重新构建的 CLI
验证发出的限制、实际文件工具执行及最终完成。测试现有全局与工作区迁移、
自定义设置保留、注释、回执及幂等性。通过有界的原生服务和网关合成请求验证
预算耗尽与预算充足的情况，不重放用户的编辑请求。

运行构建、类型检查、相关测试及桌面发布检查。同步所有 HomeCode 版本，然后
验证完整应用签名、DMG、打包运行时校验和、启动及版本。在构建 Mac 上测试
Apple Silicon 安装包并不能证明其在第二台实体 Mac 上的兼容性。临时签名
不同于 Developer ID 签名与公证。
